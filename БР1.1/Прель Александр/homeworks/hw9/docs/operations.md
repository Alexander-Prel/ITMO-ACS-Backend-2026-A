# Эксплуатация

**ВМ.** На выделенном сервере Ubuntu 24.04 внешний Nginx принимает HTTP на порту 8080 и передаёт его на локальный порт 8200. Через него трафик поступает в контейнер Nginx и далее в Gateway. Настройки экземпляра хранятся в /opt/itmo-booking/shared. Текущая версия доступна по ссылке current в том же каталоге.

**Kubernetes.** Используется namespace booking-sem2. Внешняя точка входа — Service gateway. У четырёх сервисов с SQLite и брокера отдельные PVC. Число подов Gateway задаёт HPA. Для диагностики выполните kubectl -n booking-sem2 get pods,pvc,svc,hpa и kubectl -n booking-sem2 describe hpa gateway.

**Проверка готовности.** GET /health проверяет процесс Gateway. GET /ready опрашивает Accounts, Catalog, Bookings и Notifications. При потере брокера сервис может отвечать на /health, пока общий /ready возвращает 503.

**Логи и метрики.** На ВМ откройте дашборд Grafana «Бронирование столиков · ВМ» через SSH-туннель на localhost:3300. Состояние отдельных сервисов доступно на панели probe_success. Логи контейнеров доступны в Loki по запросу {job="docker"}. В облаке сравнивайте CPU, HTTP latency и число реплик за одно и то же окно нагрузки.

**Данные и обновление.** Перезапуск пода сохраняет PVC. Перед обновлением схемы SQLite создайте резервную копию с остановленной записью. Для отката кода примените сохранённый release.yaml успешной сборки и повторите /ready и Postman. Восстановление несовместимой схемы требует резервной копии.
